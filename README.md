# CDACF Simulation — Reproducibility Repository (v4.0.0)

Complete simulation code, seeds, analysis scripts and result files for the manuscript:

> **A Stability-Governed Controller for Cross-Domain Consensus Selection in
> Blockchain-Based Heterogeneous IoT Deployments**
> Smita Bhore, Natraj N. A. — Discover Computing (under review)

No third-party or external datasets are used. Every number and figure in the manuscript is
generated by the code here, using seeds 5 to 34.

---

## What changed in v4.0.0

This release accompanies the fourth-round revision and differs substantially from v1.0.0.

| Change | Detail |
|---|---|
| Seeds | 5 to 34 (30 seeds). Seed 42 is no longer used anywhere. |
| Statistics | Independent-groups Mann-Whitney replaced by seed-paired exact permutation and Wilcoxon signed-rank, with bootstrap intervals and TOST equivalence testing. |
| New analyses | Probabilistic global sensitivity over the mechanism attribute matrix and weight profiles; full detection confusion matrices; Bayesian-versus-plain-threshold comparison; 25,000-step battery run; 13-configuration out-of-distribution sweep; held-out third domain profile. |
| Metric renamed | `threat_prevention` is now `posture_index`. The quantity is unchanged; the name was misleading. See `analysis/run_paired_stats.py` and Section 3.5.3 of the manuscript for its definition. |
| Corrections | ADACON citation year 2025 (was 2026); stability-layer docstring now states the implemented dwell periods (10 / 15 steps) and improvement threshold (0.08); revision-process comments removed. |

The numerical behaviour of the simulator is **unchanged** from v1.0.0. Renaming and comment
removal only; every reported value reproduces exactly.

## Reproducing the paper

Run from the repository root, in this order. Scripts resolve their own paths, so the working
directory does not matter.

```bash
python analysis/run_seeds.py              # ~45 s
python analysis/run_paired_stats.py       # ~30 s
python analysis/run_equivalence.py        # ~5 s
python analysis/run_detector_audit.py     # ~2 min
python analysis/run_domain_shift.py       # ~40 s
python analysis/run_sensitivity.py        # ~3 min
python analysis/run_global_sensitivity.py # ~10 min (300 draws x 12 runs)
python analysis/make_figures.py           # ~10 s
```

`run_global_sensitivity.py` accepts a draw count as its first argument, for example
`python analysis/run_global_sensitivity.py 50` for a faster check.

## Seeds

- **Evaluation:** 5 to 34.
- **Threshold recalibration** (`run_detector_audit.py`): 100 to 109, disjoint from evaluation.
- **Global sensitivity** (`run_global_sensitivity.py`): 1000 to 1299, one per draw.

All seeds are fixed in the scripts. The simulator is deterministic given a seed, so every
run in the manuscript is exactly reproducible.

## Scope of the evidence

Please read this before drawing conclusions from the outputs.

Threat conditions are simulated as additive telemetry perturbation together with a change to
a node population. The threat indicators are linear functions of the same telemetry. The
results therefore characterise the **response of the controller** to rising indicators. They
establish nothing about the security of the underlying consensus protocols under
protocol-level adversarial behaviour, which would require adversarial validator agents.

Two further properties of the model, documented in the manuscript and repeated here:

1. `posture_index` is a closed-form function of the mechanism attribute table, telemetry and a
   binary detection term. It counts no events, and outside threat windows it evaluates to the
   constant 0.98.
2. Node count does not enter the telemetry-generating process. Varying it across two orders of
   magnitude produces identical results.
